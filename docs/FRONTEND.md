# FRONTEND.md - ShelfArr Vue SPA

## Overview
ShelfArr’s frontend is a Vue 3 Single-Page Application rendered from `app/static/dist/index.html`. FastAPI serves the SPA for any non-API route via the fallback described in `docs/jinja_migration_changes.md`, while Vue Router (history mode) manages client-side navigation across all views.

## Project Layout
- `build/frontend/src/main.js` – Vue entrypoint bootstrapping App.vue, router, Naive UI, and global styles.
- `build/frontend/src/App.vue` – Root shell with layout and nav composition.
- `build/frontend/src/router/` – Vue Router configuration and route guards.
- `build/frontend/src/views/` – Page-level views: Search, History, Showcase, Logs, Series.
- `build/frontend/src/components/` – Reusable UI (NavBar, HealthIndicator, ResultRow, HistoryRow, ActionButton, StatusBadge, ShowcaseCard, etc.).
- `build/frontend/src/composables/` – Shared logic (`useApi`, `useCoverLoader`, `useImport`, live updates, Naive UI table helpers).
- `build/frontend/src/styles/global.css` – Vue-specific global styling.
- `build/frontend/src/theme/naive.js` – Naive UI theme tokens.
- `app/static/dist/` – Built assets generated by Vite (`npm run build`).

## Core Technologies
- **Vue 3 (Composition API)** powering all SPA behavior.
- **Vite** for dev server, bundling, and manifest generation.
- **Vue Router** in history mode with catch-all redirect for unknown paths.
- **Naive UI** component library themed to match ShelfArr branding.
- **Custom composables** for API access (`useApi` wrapping `@core/api.js`), cover loading (`useCoverLoader` leveraging `@services/coverLoader.js`), import workflows, and Naive UI data table utilities.

## Routing & Views
- `/` → **Search** view (search MAM, add torrents, inline library indicators).
- `/history` → **History** view (imports, verification badges, live updates).
- `/showcase` → **Showcase** view (grid of grouped editions with quick add).
- `/logs` → **Logs** view (Naive UI log viewer backed by `/logs` API).
- `/series` → **Series** view (Hardcover-driven series discovery).
- `/:pathMatch(.*)*` → catch-all redirect to `/` (handled in `build/frontend/src/router/index.js`), ensuring 404s land on the SPA home.

## Components & Composables
- **Reusable components:** StatusBadge, ActionButton, ResultRow, HistoryRow, ShowcaseCard, NavBar, HealthIndicator, Glass UI elements, and icon set under `components/`.
- **Naive UI helpers:** `composables/naive/useMAMSearchDataTable.js`, `useSeriesDataTable.js`, `useCover.js`, `useDetailView.js` provide column definitions, renderers, and table behaviors.
- **API & data utilities:** `useApi` centralizes HTTP calls through the shared FastAPI client; `useCoverLoader` streams covers via the cached cover loader; `useImport` coordinates import actions and status updates; `useHistoryLiveUpdates` polls/streams history changes.
- **Path aliases:** Defined in `build/frontend/vite.config.js` (`@components`, `@views`, `@core`, `@services`, `@composables`) to simplify imports and keep parity with shared JS utilities in `app/static/js/`.

## Styling Architecture
- **Shared base CSS:** `app/static/css/main.css` supplies variables, typography, layout primitives, tables, and utilities consumed by both legacy assets and the SPA.
- **Legacy isolation:** `app/static/css/legacy.css` holds styles retained only for legacy pages; the SPA does not rely on these beyond shared base tokens.
- **Vue globals:** `build/frontend/src/styles/global.css` adds SPA-only effects (e.g., Naive UI DataTable shimmer) and complements component scopes.
- **Scoped component styles:** `<style scoped>` blocks live with each component (StatusBadge, ActionButton, HistoryRow, LogsView, ShowcaseCard, etc.) to keep feature-specific styles encapsulated.
- **Naive UI overrides:** The theme in `build/frontend/src/theme/naive.js` maps ShelfArr’s palette and radii onto Naive UI components; tokens pair with CSS variables in `main.css`.
- For history of the split and cleanup rationale, see `docs/css_refactoring_summary.md`.

## Theme System
`build/frontend/src/theme/naive.js` exports `customTheme`, defining colors, typography, radii, and component-specific tweaks (DataTable, Pagination, Select, Input, Button, Card, Tag). Theme tokens align with CSS variables defined in `app/static/css/main.css`, ensuring Naive UI components match the base styles without separate template overrides.

## Build & Deployment Workflow
- **Install & develop:** From `build/frontend/`, run `npm install` then `npm run dev` (proxies API requests to FastAPI for local development).
- **Production build:** `npm run build` emits assets to `app/static/dist/` with manifest output and the correct base path.
- **Docker flow:** Docker builds should run the Vite build step so `app/static/dist/` exists in the final image; FastAPI serves the compiled assets via `/static/dist/` and the catch-all fallback.

## Migration Status & Legacy Interop
- Jinja templates and `app/static/pages` scripts were removed (see `docs/jinja_migration_changes.md`); SPA fallback in `app/main.py` now owns HTML responses.
- Legacy CSS persists only in `app/static/css/legacy.css` for any remaining non-Vue surfaces; shared styles remain in `main.css`.
- SPA routes rely exclusively on the Vue bundle; direct URL loads and refreshes work because of the FastAPI fallback plus Vue Router catch-all.

## Future Enhancements
- Remove `legacy.css` once remaining legacy pages are retired and all routes run through the SPA.
- Expand Naive UI adoption for any remaining bespoke controls and align more components with the theme tokens.
- Add dynamic routes (e.g., series detail pages) leveraging the existing catch-all and SPA fallback.
- Broaden composable coverage (e.g., additional API helpers, shared pagination/sorting utilities) as new views arrive.
